# 浪浪山：妖怪合伙人

面向手机和电脑的西游风妖怪对战网页游戏。当前为 **v3 试玩版**：支持单人巡山、房间制 1v1 和四人 2v2，规则和数值仍需继续试玩平衡。游戏设计与实现进度见 [游戏设计清单](游戏设计清单.md)。

## 开始游戏

```bash
python3 -m http.server 8802
```

在浏览器打开 `http://127.0.0.1:8802/`。同一局域网的手机可访问电脑的局域网 IP 和端口 8802。也可以直接打开 `浪浪山单文件版.html`：卡牌图片和脚本已内嵌，单人玩法无需网络；在线房间仍需连接云端中继。

新玩家免费抽取三只不同妖怪，至少一只为 SR 或以上；新手引导可以跳过，也可从玩法指南重新进入。游戏进度保存在当前浏览器；浏览器的不同网址、设备或无痕模式通常不共享存档。v2 存档会迁移为独立的 v3 存档，原存档保留。

## 当前玩法

- **地界与技能**：山岭克水府、水府克炎荒、炎荒克山岭，幽洞中立。每只妖怪携带四个技能，以 PP 限制使用；竞技中统一为 30 级并开放技能池。
- **巡山收服**：四地界可探索野生妖怪，使用收妖葫芦收服；重复收服获得经验果。妖怪升级解锁技能，体力和 PP 可用道具或队伍休整恢复。
- **竞技**：每人选择三只不同妖怪，可使用自己的名册以及八只免费公共妖怪。赛前配置技能和携带道具，双方可查看队伍及道具。2v2 每人指挥自己的妖怪。
- **AI 与出局**：1v1 和 2v2 的空位可由房主添加或移除 AI。2v2 中自己的妖怪全部倒下后可继续观战或离开，离开会放弃本场奖励；若离开的是房主，仍需保持页面打开，直至队友对战结束，因为房主浏览器负责结算。
- **等待与恢复**：选招和替补选择限时 60 秒；断线检测后暂停等待重连，60 秒后判负。刷新页面可在同一浏览器标签页尝试恢复未结束的对战。
- **对战表现**：技能、目标与替补需选择并确认；回合结算按顺序播放，真人播放完成后开始下一回合计时，等待上限为 15 秒。胜负确定后聚焦最后击倒，可跳过动画。特效遵循系统“减少动态效果”设置自动降级。手机使用纵向布局，宽屏使用场地与操作区并排布局。

对战节奏以约 2 分钟一场为试玩目标，实际时长取决于选招、阵容、特效与网络。伤害随攻击者等级增长；四人对战的直接伤害额外提高 25%，以适应双方更多妖怪。疗伤烧饼和治疗技能恢复最大体力的 20%，护心果恢复 15%；这些数值仍需真人试玩验证。

平衡试玩调整：红孩儿与白骨精减少少量攻击和速度、增加体力；铁扇公主和玉面狐狸提高攻击并相应调整其他属性。护身佩首次直接伤害减免提高到 50%；SSR 和 UR 野生妖怪的收服概率提高。调整仍需结合真人 1v1、2v2 和巡山体验验证。

竞技依赖现有的云端房间中继，房主浏览器负责结算。它适合受信任玩家试玩，当前没有服务端身份校验和防作弊机制，不能视为可用于正式排位赛事的安全竞技服务。网络短暂中断、浏览器后台限流或中继不可用都可能影响联机；恢复功能依赖同一标签页的临时会话数据。

## 测试与生成分享版

需要 Node.js 和 Python 3，无需安装项目依赖：

```bash
node tests/game-v3.test.cjs
node tests/game-fx-queue.test.cjs
node tests/balance-audit.cjs
python3 build_singlefile.py
```

测试覆盖属性、公共卡池、技能、目标、切换、超时、断线、道具、收服、存档迁移及模拟对局。生成脚本从 `cards/` 编码图片并内联脚本，重新生成 `浪浪山单文件版.html`；修改页面、脚本或卡图后应重新生成。

平衡审计脚本固定随机种子，让八只公共妖怪逐对单挑并使用预设配招中的攻击技能。它只用于发现明显差距，不包括换人、道具、辅助技能和 2v2 配合，也不能替代真人试玩。

## 主要文件

- `index.html`：页面、房间中继与兼容原版存档的界面入口。
- `game-rules-v3.js`：属性、妖怪能力、技能、竞技道具和巡山规则。
- `game-engine-v3.js`：可序列化的战斗状态与回合结算。
- `game-arena-v3.js` / `game-arena-ui-v3.js`：竞技调度与房间界面。
- `game-fx-v3.js`：战斗特效层，把引擎事件转为顺序表演（可测试的 `plan` 与 DOM 播放的 `play`）。
- `game-solo-ui-v3.js`：单人巡山界面与战斗适配。
- `game-save-v3.js`：本机存档与旧版迁移。
- `wb-cloud.js`：原有云服务 SDK；联机依赖它与现有云端配置。
- `tests/game-v3.test.cjs` / `tests/game-fx-queue.test.cjs`：规则、存档及战斗特效队列测试。

`index.html` 仍保留部分旧版战斗与房间兼容代码，后续清理时应同时维护单人、联机、引导和旧存档回归测试。
